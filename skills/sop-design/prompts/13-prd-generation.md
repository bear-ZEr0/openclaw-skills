# 阶段13: PRD文档生成 (PRD Generation)

## 阶段目标
整合所有阶段的产出，生成完整的可执行PRD文档。

## AI角色
**文档工程师** - 组装、格式化、输出

## 输出格式

使用 templates/prd-template.md 模板，填入所有阶段的内容。

## ⚠️ 重要：必须完成所有前置阶段

**在进入 PRD 生成之前，必须确保已完成：**
- [ ] Phase 1-4 需求分析（功能、流程已确定）
- [ ] Phase 5-6 功能规格（验收标准已定义）
- [ ] Phase 7 UI/UX 设计（页面布局已完成）
- [ ] Phase 8 技术探索（技术选型已确认）
- [ ] Phase 9 架构设计（模块划分已完成）
- [ ] Phase 10 风险评估（风险已识别）
- [ ] Phase 11 实施规划（Sprint 划分已完成）
- [ ] Phase 12 验证测试（测试策略已制定）

**禁止跳过任何阶段！** 如果前置阶段未完成，先回去完成。

## 生成步骤

```
读取PRD模板
    ↓
检查所有前置阶段产出
    ↓
填入各阶段内容
    ↓
格式化调整
    ↓
添加目录和交叉引用
    ↓
输出完整PRD
```

## 📋 PRD 组装检查清单

### 1. 文档头部
- [ ] 版本号（v1.0）
- [ ] 日期
- [ ] 状态（草稿/评审中/正式版）
- [ ] 作者

### 2. 产品概述（来自 Phase 1-2）
- [ ] 产品名称
- [ ] 产品定位
- [ ] 目标用户
- [ ] 解决的问题

### 3. 竞品分析（来自 Phase 3）
- [ ] 市场概况
- [ ] 竞品对比表格
- [ ] 差异化优势

### 4. 功能清单（来自 Phase 4-5）
- [ ] MVP 功能（Must）
- [ ] 扩展功能（Should/Could）
- [ ] 未来功能（不在本期）

### 5. 功能规格（来自 Phase 5-6）
- [ ] 每个功能有 ID、描述、验收标准
- [ ] 验收标准格式：Given-When-Then

### 6. UI/UX 规范（来自 Phase 7）
> 必须引用详细设计文档，格式：`> 详细设计见 [文档名称](../路径)`

- [ ] 设计规范摘要（色彩、字体、间距）
- [ ] 页面结构
- [ ] 交互流程
- [ ] **引用** `../ui-design/app-ui-description.md`

### 7. 技术方案（来自 Phase 8-9）
> 必须引用架构设计文档

- [ ] 技术栈列表
- [ ] 架构图/模块划分
- [ ] 数据库设计
- [ ] **引用** `../architecture/architecture-design.md`

### 8. 实施计划（来自 Phase 9）
- [ ] Sprint 划分
- [ ] 里程碑
- [ ] 时间线

### 9. 风险评估（来自 Phase 10-11）
- [ ] 风险矩阵
- [ ] 应对策略
- [ ] 预算估算

### 10. 非功能需求（来自 Phase 10）
- [ ] 性能要求
- [ ] 兼容性要求
- [ ] 安全要求
- [ ] 验收条件

### 11. 附录
> 添加附录说明详细设计文档的位置

```markdown
## 附录：详细设计文档

| 文档 | 路径 | 说明 |
|------|------|------|
| UI/UX 详细设计 | ../ui-design/xxx.md | 页面布局、交互流程 |
| 架构设计 | ../architecture/xxx.md | 模块化设计、可扩展性 |
```

## ⚠️ 能力边界提醒

**AI 可以做的：**
- ✅ 生成详细的 UI 描述文档（文字）
- ✅ 生成架构设计文档
- ✅ 生成代码框架

**AI 做不到的：**
- ❌ 直接生成 UI 图片/Figma 设计图
- ❌ 生成可安装的 App
- ❌ 直接调用付费 API

**遇到图片需求时：**
- 提供详细的 UI 描述文档（用户可自己生成图片）
- 或建议使用 Figma/Mastergo/即时 AI 等工具

## 📊 任务分片建议（防止超时）

如果项目较大，将 PRD 生成分批进行：

```
批次1: 产品概述 + 竞品分析 + 功能清单
批次2: 功能规格（每个功能单独验证）
批次3: UI/UX + 技术方案 + 引用文档
批次4: 实施计划 + 风险评估 + 附录
```

**每批次完成后汇报进度。**

## 注意事项

1. **禁止跳过阶段** - 必须完成所有前置阶段才能生成 PRD
2. **引用详细文档** - UI/UX 和架构必须引用详细设计文档
3. **保持链接** - 确保各个章节之间的引用正确
4. **格式统一** - 使用一致的表格和列表格式
5. **版本信息** - 每次生成/修改都更新版本号和日期
6. **批准区域** - 在文档末尾预留用户签字确认的区域
7. **检查清单优先** - 生成前必须执行组装检查清单，不能跳过
8. **草稿标记** - 如有未完成阶段，在文档头部标记 `状态: 草稿（[X]阶段待补充）`
9. **Mermaid验证** - 确保所有流程图语法正确，特别是中文字符处理
