# 阶段10: 可测试性设计 (Testability Design) ⭐核心

## 阶段目标
为每个功能定义清晰的验收标准和测试规范，确保PRD可被后续AI用于代码和测试生成。

## AI角色
**测试设计师** - 定义可验证的验收标准

## 核心原则

**这个阶段的产出是AI写代码和生成测试文档的直接依据！**

每个功能必须有：
1. 清晰的输入定义
2. 明确的输出定义
3. 具体的边界条件
4. Given-When-Then格式的验收标准
5. 测试要点（Happy Path + 异常场景 + 边界测试）

## Given-When-Then 格式

```
[验收标准名称]
Given: [前置条件]
When: [用户操作/触发条件]
Then: [预期结果1]
  And: [预期结果2]
  And: [预期结果3]
```

## 用户交互流程

```
选择功能
    ↓
定义输入/输出
    ↓
列举边界条件
    ↓
编写Given-When-Then验收标准
    ↓
列出测试要点
    ↓
下一个功能
```

## 示例

### 示例: "开始番茄钟"功能的测试规格

```markdown
## 功能测试规格: F-001 开始番茄钟

### 功能描述
用户输入任务名称后，启动一个25分钟的番茄钟倒计时。

### 前置条件
- 应用已安装并启动
- 用户位于首页
- 没有正在进行的番茄钟

### 输入定义

| 字段名 | 类型 | 必填 | 约束条件 | 默认值 |
|--------|------|------|----------|--------|
| taskName | String | 是 | 长度1-50字符，不能全为空格 | - |
| duration | Int | 否 | 15-60分钟 | 25 |

### 输出定义

| 字段名 | 类型 | 说明 | 成功时 | 失败时 |
|--------|------|------|--------|--------|
| success | Boolean | 是否成功启动 | true | false |
| timerId | String | 计时器ID | UUID | null |
| startTime | Long | 开始时间戳 | 时间戳 | null |
| errorMessage | String | 错误信息 | null | "任务名称不能为空" |

### 边界条件

1. **边界1: 任务名称为空**
   - 处理方式: 显示错误提示，不启动计时
   - 预期结果: success=false, errorMessage="请输入任务名称"

2. **边界2: 任务名称过长（>50字符）**
   - 处理方式: 截断至50字符或报错
   - 预期结果: 根据产品决策，需明确

3. **边界3: 已有进行中的番茄钟**
   - 处理方式: 提示用户已有进行中的计时，询问是否覆盖
   - 预期结果: 显示确认对话框

4. **边界4: 应用切换到后台**
   - 处理方式: 计时继续在后台运行，显示通知
   - 预期结果: 通知栏显示倒计时

### 验收标准 (Acceptance Criteria)

#### AC1: 成功开始番茄钟 - Happy Path
```
Given: 用户在首页
  And: 输入框中输入"学习英语"
When: 用户点击"开始"按钮
Then: 页面跳转到计时中页面
  And: 显示25分钟倒计时
  And: 显示任务名称"学习英语"
  And: 生成计时器ID并保存到本地
  And: 记录开始时间
  And: 启动后台计时服务
```

#### AC2: 任务名称为空 - 异常场景
```
Given: 用户在首页
  And: 输入框为空
When: 用户点击"开始"按钮
Then: 显示错误提示"请输入任务名称"
  And: 页面不跳转
  And: 不启动计时
```

#### AC3: 任务名称超长 - 边界场景
```
Given: 用户在首页
  And: 输入框中输入51个字符的任务名称
When: 用户点击"开始"按钮
Then: 截断至50字符并启动计时
  And: 显示提示"任务名称已自动截短"
```

#### AC4: 后台运行 - 边界场景
```
Given: 番茄钟正在进行中
When: 用户切换到其他App
Then: 计时继续在后台运行
  And: 通知栏显示倒计时
  And: 时间到后播放提示音
```

### 测试要点

#### Happy Path 测试
- [ ] 正常输入任务名称，成功启动番茄钟
- [ ] 验证计时器正确倒计时
- [ ] 验证数据正确保存到本地

#### 异常场景测试
- [ ] 空任务名称，显示错误
- [ ] 全空格任务名称，显示错误
- [ ] 特殊字符任务名称，正常处理

#### 边界测试
- [ ] 任务名称1字符，正常启动
- [ ] 任务名称50字符，正常启动
- [ ] 任务名称51字符，截断处理
- [ ] 已有进行中的番茄钟，正确处理
- [ ] 后台运行，计时继续
- [ ] 手机重启，恢复计时状态

### 相关UI组件
- taskNameInput: 任务名称输入框
- startButton: 开始按钮
- timerDisplay: 倒计时显示
- errorToast: 错误提示

## 注意事项

1. **每个功能都要写** - 不要省略，这是后续代码和测试的依据
2. **Given-When-Then要具体** - 不要模糊，要能直接翻译成测试代码
3. **边界条件要全面** - 考虑空值、超长、并发、中断等情况
4. **输出要明确** - 成功和失败的输出都要定义清楚
5. **测试数据要真实** - 提供可用于测试的真实数据示例
6. **Happy Path + 异常 + 边界** - 三类测试都要覆盖
