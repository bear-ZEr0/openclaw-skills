# 阶段2: 需求结构化解析 (Requirement Structuring)

## 阶段目标
通过主动提问澄清模糊点，补全隐含需求，定义产品边界。

## AI角色
**需求分析师** - 深度挖掘需求，帮助用户想清楚

## 核心提问清单

### 用户相关
1. "目标用户是谁？"（年龄/职业/技术水平）
2. "用户会在什么场景下使用这个产品？"
3. "用户的核心痛点是什么？"

### 功能相关
4. "最核心必须有的功能是什么？"（Must have）
5. "有了会更好但不是必须的功能？"（Nice to have）
6. "哪些功能明确不做？"

### 技术相关
7. "需要离线使用吗？"
8. "数据存储在哪里？"（本地/云端/混合）
9. "有预算限制吗？"（付费API/服务器成本）

### 商业相关
10. "盈利模式是什么？"（免费/付费/订阅）
11. "竞品有什么你特别不喜欢的功能？"
12. "你的产品差异化在哪里？"

## 用户交互流程

```
展示初步需求摘要
    ↓
依次提出澄清问题
    ↓
记录用户回答
    ↓
补全隐含需求
    ↓
定义MVP边界
    ↓
输出结构化需求
```

### 2. 功能需求

- [ ] 功能5: [描述]

- [ ] 功能6: [描述原因]

### 3. 技术约束
| 约束项 | 决策 |
|--------|------|
| 网络要求 | [离线/在线/混合] |

## 示例

### 示例: 番茄钟App

**AI提问与记录**:

> AI: "目标用户是谁？"
> 用户: "主要是大学生和上班族，需要提高专注力"

> AI: "最核心必须有的功能是什么？"
> 用户: "计时功能，可以设置25分钟工作+5分钟休息"

> AI: "需要离线使用吗？"
> 用户: "是的，有时候在图书馆没网也要能用"

> AI: "明确不做的功能有哪些？"
> 用户: "不要做社交功能，不要登录系统，简单点"

**AI输出**:

```markdown
## 结构化需求文档

### 1. 用户画像
| 维度 | 描述 |
|------|------|
| 目标用户 | 大学生和上班族 |
| 用户年龄 | 18-35岁 |
| 技术水平 | 普通手机用户 |
| 使用场景 | 学习、工作场景 |
| 核心痛点 | 难以保持专注，容易被手机干扰 |

### 2. 功能需求

#### Must Have
- [ ] 番茄钟计时 (25分钟工作+5分钟休息)
- [ ] 离线使用
- [ ] 本地数据存储

#### Should Have
- [ ] 白噪音背景音
- [ ] 每日统计

#### Could Have
- [ ] 自定义时长
- [ ] 数据导出

#### Won't Have
- [ ] 用户登录系统 (保持简单)
- [ ] 社交功能 (保持专注)
- [ ] 云端同步 (成本考虑)

### 3. 技术约束
| 约束项 | 决策 |
|--------|------|
| 网络要求 | 完全离线可用 |
| 数据存储 | 本地SQLite |
| 平台 | Android优先 |
| 预算 | 有限，避免付费API |

### 4. 产品边界
#### MVP范围
- 基础番茄钟计时
- 本地数据存储
- 简单统计

#### 明确不做
- 社交分享
- 云端账号
- 复杂的数据分析

### 5. 成功指标
- [ ] 用户能顺利完成一个番茄钟
- [ ] 应用在离线状态下正常运行
- [ ] 启动时间 < 2秒
```

## 注意事项

1. **Must Have 不能超过5个** - 确保MVP足够小
2. **明确记录 Won't Have** - 防止范围蔓延
3. **确认技术约束** - 避免后续方案不可行
4. **量化成功指标** - 让目标可衡量
