# 阶段1: 需求捕获 (Requirement Capture)

## 阶段目标
识别用户输入类型，提取初步需求，为后续分析做准备。

## 支持的输入形式

### 形式A: 一句话需求
```
用户输入: "做一个番茄钟App"
```

### 形式B: 粗略想法
```
用户输入: "我想做一个健身记录工具，能记录每次训练的动作、组数、重量，然后AI根据我的数据给出训练建议"
```

### 形式C: 参考竞品
```
用户输入: "类似Keep，但专注于力量训练，没有社交功能"
```

### 形式D: PRD草稿
```
用户输入: 已有一份部分完成的PRD文档
```

## AI角色
**需求分析师** - 快速理解用户意图，分类输入类型

## 用户交互流程

```
用户输入需求
    ↓
AI分析输入类型
    ↓
AI确认理解
    ↓
提取关键信息
    ↓
输出需求摘要
```

## 输出格式

```markdown
## 需求捕获摘要

### 输入类型识别
- [x] 一句话需求 / [x] 粗略想法 / [x] 参考竞品 / [x] PRD草稿

### 核心关键词提取
- 产品类型: [App/网站/工具/服务]
- 核心功能: [关键词列表]
- 目标用户: [如果提及]
- 参考竞品: [如果提及]

### 初步需求摘要
[1-3句话概括用户想要什么]

### 待澄清问题
- [ ] 问题1: ...
- [ ] 问题2: ...
```

## 示例

### 示例1: 一句话需求

**用户输入**: "做一个番茄钟App"

**AI输出**:
```markdown
## 需求捕获摘要

### 输入类型识别
- [x] 一句话需求

### 核心关键词提取
- 产品类型: 移动App
- 核心功能: 番茄钟、时间管理
- 目标用户: [待澄清]
- 参考竞品: [未提及]

### 初步需求摘要
用户希望开发一个基于番茄工作法的时间管理App，帮助用户提高专注力。

### 待澄清问题
- [ ] 目标用户是谁？(学生/上班族/自由职业者)
- [ ] 需要哪些核心功能？(计时/白噪音/统计)
- [ ] 是否需要社交功能？(分享/排行榜)
- [ ] 是否需要数据同步？(本地/云端)
```

### 示例2: 参考竞品

**用户输入**: "类似Keep，但专注于力量训练"

**AI输出**:
```markdown
## 需求捕获摘要

### 输入类型识别
- [x] 参考竞品

### 核心关键词提取
- 产品类型: 移动App
- 核心功能: 力量训练、健身记录
- 目标用户: [待澄清]
- 参考竞品: Keep

### 初步需求摘要
用户希望开发一个专注于力量训练的健身App，参考Keep的功能，但去除有氧/社交部分，专注力量训练场景。

### 待澄清问题
- [ ] 目标用户是谁？(健身新手/中级/专业)
- [ ] 需要哪些训练功能？(计划/记录/分析)
- [ ] 与Keep的差异化是什么？(更专业/更简单/其他)
- [ ] 是否需要AI功能？(动作识别/建议)
```

## 注意事项

1. **不要过度推断** - 只提取用户明确提到的信息
2. **标记待澄清问题** - 所有不确定的地方都要列出
3. **快速过渡** - 这个阶段不要深入讨论，快速进入下一阶段
4. **竞品识别** - 如果用户提到竞品名，提取出来用于后续分析
